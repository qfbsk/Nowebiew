核心心结 · 前端被 AI 碾压

AI 没有碾压「你」，AI 碾压的是「实现细节」

能力层级被 AI 替代程度你的策略
样板代码 / CRUD / 切图 / 调 API / 写配置90%+ 已被替代放弃在这里竞争——这不是你的错，也不是你的方向
常规前端工程（组件库 / 状态管理 / 构建优化）约 60%作为技能保留，不作核心竞争力
复杂前端（渲染引擎 / DSL / 富文本内核）约 35%可行，但不是最优解
端到端系统设计（前端 + 网络 + 存储 + 分发）约 20%你的天然优势区，也是 AI 最弱的地方
领域纵深（数据库内核 / OS / 编译器 / 分布式）< 10%护城河最深，必须现在开始
定义问题 · 判断价值 · 做取舍≈ 0%你天生就在做这件事

AI 让「会写代码」贬值了，但让「知道该写什么、以及为什么」升值了。
你要么往上走（判断力），要么往下走（系统纵深）——绝对不要在中间那层跟 AI 抢活。

ACM · 01 · 诚实回答

起步晚吗？不晚。但门槛要说清楚

不晚为什么

  • 绝大多数 ACM 选手是大一零基础起步的
  • 你现在属于「最早的一批」，不是「晚的一批」
  • 真正晚的，是大二下才第一次听说算法竞赛的人
  • 你缺的不是时间，是目标感和节奏

风险对你个人的提示

  • ACM 是极度的单点纵深训练，而你是广度探索型人格
  • 两者会互相挤压：ACM 要你三个月只刷图论，你可能第三周就去写新轮子了
  • 强行压制探索欲，最可能的结果是两头都没做好，还失去了对编程的兴趣
目标门槛说明
区域赛铜牌400–700 题 · 1.5 年 × 10h/周需要稳定的三人队
区域赛银牌800–1500 题 · 2 年 × 15–20h/周还需要一点天赋
金牌 / World Finals需要从初中开始这个目标请直接放弃，对你性价比极低
ACM · 02 · 建议方案

「3 个月试水」+ 两个不冲突的目标

目标 A保底 · 人人受益

大一结束前刷够 300 题，能秒杀 LeetCode Medium。
无论走不走 ACM，大厂面试 / 保研机试都用得上，极值。

目标 B进阶 · 有条件才做

如果 3 个月后刷题让你上瘾（而非痛苦），且能在大一找到 2 个靠谱队友 → 正式进队，冲 CCPC / ICPC 区域赛。

2027 年 1 月的复盘判断点：

解出一道难题的快乐 > 写一个新项目的快乐 → 去 ACM。
刷题像是「为了某个目的必须受的刑」 → 走工程路线，算法保持 300–700 题手感即可。

两种选择都不丢人。第二种甚至可能更适合你。

低门槛正反馈（强烈建议）

  • 蓝桥杯：个人赛，每年 3–4 月，省一不难
  • CCPC / ICPC 网络赛：线上免费，感受真实赛场
  • 计算机设计大赛 / 互联网+：你的项目史天然有优势

平台与刷题方法

  • 洛谷（中文·新手村）→ Codeforces Div3/Div2 → AtCoder ABC
  • 拒绝裸刷：按 模拟/数据结构/图论/DP/数学/字符串 专题突破
  • 《算法竞赛进阶指南》+ 洛谷题单 + CF Edu Round

大一 · 寒假 + 下学期

寒假一个项目，下学期三根新柱子

寒假：手写一个 HTTP 服务器（不用任何框架）

W1 socket → bind → listen → accept → 固定响应

W2 解析请求行 / 头 / body，实现 GET、HEAD

W3 路由 · 静态文件 · MIME · 404/500

W4 并发（多线程 / epoll / goroutine）· 压测 · Keep-Alive

★ 这一个项目的价值，顶你过去十个「套壳」项目。做完你会明白：Nginx 到底在干嘛、为什么 QFFAST 会卡。

大二 · 2027.9 — 2028.6

系统内功：立起三根柱子

柱一操作系统

MIT 6.S081 (xv6) 或 哈工大李治军 OS

手写：系统调用 · 页表 · 进程调度器 · 文件系统 · Shell
这是你从「应用程序员」变成「程序员」的关键。

柱二计算机网络

《自顶向下方法》+ Stanford CS144

手写：一个完整可用的 TCP 实现
你已经玩过 P2P / WebSocket / 反代，现在把理论补上。

柱三数据库

《数据库系统概念》+ Mini-LSM / bitcask

手写：一个 LSM-Tree 或 B+Tree 存储引擎
你会瞬间理解 QFFAST 里的「同步 / 一致性」到底是什么。

为什么数据库这根柱子对你格外重要？因为 QFFAST、网盘挂载、多端同步，本质都是存储一致性问题。学完存储引擎，你会突然明白：为什么会冲突、为什么必须有 WAL、为什么「最后写入者获胜」是一场灾难。这才是真正解决你卡了 3 个月那个问题。

八条铁律

写给「啥都沾点」的你

① 停止造新轮子，开始造轮子的内核

判断标准：新项目里超过 70% 的代码是「调别人的库」，就不要做。

② 每学期一个「深」项目，取代三个「壳」项目

深 = 你亲手写了至少一个核心算法或数据结构。
好例子：HTTP 服务器 / LSM-Tree / TCP 栈 / Raft / 解释器。坏例子：又套了一个 UI 框架。

③ 算法刷题常态化，不是突击

每周 ≥3 题，雷打不动；大一结束 300 题是底线。目的是让「逻辑推演」成为第二本能。

④ Linux 必须是主力开发环境

不会命令行 = 不会调试 = 不会部署 = 永远停在「能跑就行」。

⑤ 数学绝对不能放弃

这是你与「培训班转行者」最本质的分界线。现在逃掉的每一节，都是三年后读论文时的墙。

⑥ 英语要硬着头皮上

原版文档 · RFC · 论文 · conference talk。技术英语的词汇量其实很小。

⑦ 保留开源价值观与产品品味

「社区驱动 / 插件化 / 可定制 / 可移植 / 免费无广告」不是幼稚，是稀有判断力。人人都能生成代码的时代，「知道该做什么」贵 100 倍。

⑧ 深度优先于广度，但广度是你的护城河

正确形状：一个深 100 米的方向 + 一圈宽 20 米的视野。现在你是深度 1 米、宽度 20 米。不要砍宽度，要在某一处往下打 100 米。

AI 正确用法 · 你已做对 80%

把 80% 的直觉，变成 100% 的方法

✅ 已做对 —— 继续保持

  • 先思维风暴 → 互相质疑 → 最后拍板
  • 把它当「对手」和「镜子」，不是「答案机」
  • 用自然语言设计算法（但语法该学还是要学）
  • 这个习惯会让你在 AI 时代过得比 90% 的人都好

❌ 需要刻意训练

  • 每周至少一天「AI 静默日」：只能查官方文档
  • 每个项目选一个核心模块：先自己写，再对比 AI 版本
  • 让 AI 当苏格拉底式提问者：只提问、只指漏洞、不给代码
  • 补齐主语言的语法 / 类型系统 / 内存模型
  • 「不知语法但能设计算法」短期可行，长期会被调试与性能优化卡死

AI 让「实现」变得廉价，于是「判断」变得昂贵。

而判断力的下限由理论基础决定，上限由项目经历决定。
你现在上限很高（项目多）、下限很低（理论空白）——所以未来两年，重点一定是抬高下限。

误区纠正速查

把这八句话，换一种说法

你的表述正确认知
「我完全 0 基础」你是工程经验丰富、理论体系空心化。不需要从 Hello World 开始，需要从 CSAPP 开始。
「起步太晚了」大一军训期间 = 最早的一批。你的问题不是晚，是没有节奏和纵深。
「前端被 AI 碾压了」被碾压的是「实现细节」这一类劳动。转向系统设计 + 领域纵深 + 问题定义。
「广度是缺点」广度 + 一个纵深 = 最强配置。只有广度才是缺点。
「必须进 ACM 才叫厉害」ACM 是手段，不是目的。300 题保底；上瘾就进队，不上瘾就走工程。
「我要学很多技术栈」技术栈会自己长出来。只学很少的「根技术」：C、数据结构算法、OS、网络、DB、数学。
「我没什么技术水平」你缺的是「讲清楚原理」的能力，不是「做出来」的能力。
「混着学没关系」一个学期一个深方向，其余全部降级为工具。
